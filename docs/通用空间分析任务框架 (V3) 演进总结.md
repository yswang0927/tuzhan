# 通用空间分析任务框架 (V3) 演进总结

系统架构已经成功从单一的“轨迹查询”升级为**通用的“异步空间分析任务平台 (V3)”**。

所有的代码重构已经完成，现在的系统完全遵守开闭原则 (Open-Closed Principle)，未来接入任何复杂的新分析功能（例如：区域碰撞分析、人员轨迹碰撞、首次出现人员等）都**不需要修改现有表结构或核心调度代码**。

## 1. 核心模型替换

原有的高度定制化的表和实体已被移除，替换为通用框架：
*   **[`AsyncTask.java`](file:///Users/yswang/WorkSpace/java-projects/tuzhan/src/main/java/com/tuzhan/entity/AsyncTask.java)**: 对应数据库 `sys_async_task` 表。最关键的改变是引入了 `taskType` (任务类型) 和 `taskParams` (JSON 格式的动态查询参数)。
*   **[`AsyncTaskRepository.java`](file:///Users/yswang/WorkSpace/java-projects/tuzhan/src/main/java/com/tuzhan/repository/AsyncTaskRepository.java)**: 通用数据访问层。

## 2. 策略模式 (Strategy Pattern) 核心

我们引入了一个标准的扩展接口，任何业务分析只要实现它，就能自动获得后台调度、重试、文件落盘等所有高级特性。

*   **[`ITaskExecutor.java`](file:///Users/yswang/WorkSpace/java-projects/tuzhan/src/main/java/com/tuzhan/executor/ITaskExecutor.java)**: 执行器接口。包含 `getTaskType()` 标识自己，以及 `execute(taskParamsJson)` 处理实际业务。
*   **[`TrajectoryQueryExecutorImpl.java`](file:///Users/yswang/WorkSpace/java-projects/tuzhan/src/main/java/com/tuzhan/executor/impl/TrajectoryQueryExecutorImpl.java)**: 作为第一个接入的分析功能，实现了上述接口。原先强耦合在调度器里的对象查询逻辑现在被内聚在这个类中。

## 3. 智能调度中心与守护进程

*   **[`AsyncTaskDispatcher.java`](file:///Users/yswang/WorkSpace/java-projects/tuzhan/src/main/java/com/tuzhan/executor/AsyncTaskDispatcher.java)**: 任务路由器。它每 5 秒从数据库拉取 `PENDING` 的任务，并根据 `taskType` 自动去寻找并调用对应的 `ITaskExecutor` Bean。执行完毕后统一将结果序列化为 JSON 写入磁盘，并更新状态。
*   **[`AsyncTaskWatchdog.java`](file:///Users/yswang/WorkSpace/java-projects/tuzhan/src/main/java/com/tuzhan/executor/AsyncTaskWatchdog.java)**: 守护进程，负责超时熔断（自动将运行超过 30 分钟的任务判定失败并重试）和清理过期数据（7天前的记录与磁盘结果文件）。

## 🚀 未来如何开发新功能？（例如：区域碰撞分析）

如果明天前端需要接入“区域碰撞分析”，后端的开发流程将极其简单：

1.  创建一个新的类 `AreaCollisionExecutorImpl implements ITaskExecutor`。
2.  在里面返回类型如 `"AREA_COLLISION"`。
3.  在 `execute` 方法里：把传进来的 JSON 字符串反序列化为您的区域/时间段等参数模型，然后去查询 ClickHouse，最后返回统计对象。
4.  **完成！** 其他所有诸如“插入任务到数据库”、“排队调度”、“存为文件”、“前端轮询”、“失败重试”、“垃圾回收”等脏活累活，这套 V3 框架会自动帮您全部搞定。
